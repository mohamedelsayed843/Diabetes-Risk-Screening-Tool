# Diabetes Risk Screening Tool

An end-to-end machine learning project that classifies **self-reported diabetes status** from health and lifestyle indicators, with threshold tuning, model explainability (SHAP) and a Streamlit app.

> **⚠️ Medical disclaimer**
> This is an educational portfolio project. It is **not** a medical device, has **not** been clinically validated, does **not** diagnose diabetes and does **not** predict future diabetes onset. Do not use it to make health decisions. Consult a qualified health professional.

---

## Dataset

- **Source:** [Diabetes Health Indicators Dataset](https://www.kaggle.com/datasets/alexteboul/diabetes-health-indicators-dataset) (Kaggle), derived from the CDC **BRFSS 2015** survey.
- **File used:** `diabetes_binary_health_indicators_BRFSS2015.csv` (original, imbalanced binary version). No other dataset is used.
- **Target:** `Diabetes_binary` — `0` = no diabetes, `1` = **prediabetes or diabetes** (self-reported).
- **Features (21):** blood pressure, cholesterol, BMI, smoking, stroke, heart disease, physical activity, diet, alcohol, healthcare access, general/mental/physical health, difficulty walking, sex, age group, education, income.

The data is not included in this repository. The notebook loads it from the Kaggle input directory.

## Limitations

- Data are **self-reported survey answers** (2015), not clinical measurements or lab results.
- The model learns **associations with reported status**; it is not a diagnostic system and does not forecast future onset.
- The positive class merges prediabetes and diabetes; diabetes types are not distinguished.
- Survey weights and sampling design are ignored; results may not generalise to other populations or years.
- Features are coarse (age in 13 bands, income in 8 bands), and identical feature patterns can carry different labels, which caps achievable performance.
- Feature importance and SHAP describe **model behaviour, not causes**.
- Because class weights or SMOTE may be used, the model output is a **screening score, not a calibrated probability**.

## Project overview

| Stage | What is done |
|---|---|
| EDA | Shape, types, missing values, duplicates, conflicting-label patterns, target imbalance, distributions, correlations. Zeros and duplicates are investigated rather than blindly removed. |
| Split | Stratified train / validation / test (70 / 15 / 15). Test set is touched once, at the end. |
| Preprocessing | `ColumnTransformer` + `Pipeline`: imputation for all groups, scaling only for Logistic Regression. Fit on training data only. |
| Imbalance | Baseline vs class weights vs SMOTE, compared with stratified CV. SMOTE is applied only inside training folds (imbalanced-learn pipeline). |
| Models | Logistic Regression, Decision Tree, Random Forest, XGBoost, each tuned with `RandomizedSearchCV` (PR-AUC). |
| Evaluation | Accuracy, precision, recall, F1, ROC-AUC, PR-AUC, confusion matrices, ROC and PR curves, classification report. |
| Model selection | Highest validation **PR-AUC**, sanity-checked against recall/precision and F2. Not selected on accuracy. |
| Threshold | Chosen on **validation** data by maximising F2 (recall weighted over precision, as in screening). Never tuned on the test set. |
| Explainability | Built-in importance, permutation importance, SHAP summary / dependence / per-example plots. |
| Deployment | Saved Joblib pipeline + JSON config (threshold, metrics, library versions), shared `inference.py`, Streamlit app. |

## Quick start

### 1. Train on Kaggle

1. Create a new Kaggle notebook and import `diabetes_risk_screening_notebook.ipynb`.
2. **Add Input** → search for *Diabetes Health Indicators Dataset* by Alex Teboul.
3. Turn **Internet** on (to install any missing packages) and click **Run All**.
4. Download `diabetes_pipeline.joblib`, `model_config.json`, `inference.py`, `app.py` and `requirements.txt` from `/kaggle/working/`.
